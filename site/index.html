Why this exists

Multistreaming services charge a monthly fee to relay a stream you could already relay yourself. ffmpeg's tee muxer has done this for years. This project is a readable wrapper around it, plus an interface you can use without touching a terminal.

Free, actually

No account, no tier limits, no watermark, no minutes counter. MIT licensed.

Private by design

Encoding happens on your machine. Nothing is proxied through anyone's server.

One encode, many outputs

Your CPU encodes once and the result is duplicated. Adding a destination is nearly free.

Keys stay secret

Stream keys are encrypted at rest with AES-256-GCM and never sent back to the browser.

Works with OBS

Point OBS at the local ingest URL, or use the built-in browser studio.

Readable code

Plain Node, no framework, no build step. The whole engine is a few hundred lines.

Download

The Android app connects to a studio server you run, then gives you a camera preview and one button to go live. Requires Android 7.0 or newer.

Android APK 3.1 MB · signed release Checksums SHA-256, verify your download

Android will warn that this comes from outside the Play Store. That is expected for sideloaded apps — the APK is signed, and you can verify the checksum above. On first launch the app asks for camera and microphone access; without those the preview stays black.

Run it on your computer

Needs Node 20+ and ffmpeg on your PATH.

git clone https://github.com/blazebanditske/Streaming-software
cd Streaming-software
npm install
npm start

Then open http://localhost:8080. Add a destination, paste the stream key from your platform's dashboard, and press Go Live.

Prefer OBS? Point it at rtmp://localhost:1935/live/studio and let the studio handle the fan-out.

About TikTok

TikTok allows RTMP only for eligible accounts — roughly 1,000 followers, 18 or older, in good standing. If you qualify, TikTok works here as a first-class destination: paste the Server URL and key from Live Center, same as any other platform.

What this project will not do is fake that eligibility. Tools that advertise "stream to TikTok without a stream key" work by lifting your session token and replaying it against TikTok's private creator API. That breaks TikTok's terms and has a documented history of getting accounts shadowbanned.

Every platform preset in this codebase carries supportsAutoKey: false, and a test asserts it stays that way. The promise is enforced by the build, not just written down.

If you are not yet eligible, the guide in the repository covers four legitimate routes — including using a virtual camera with TikTok's own Live Studio, which needs no key at all and works today.

Questions

Is this really free?

Yes. MIT licensed, no account, no paid tier. You supply the computer and the internet connection; there is nothing else to buy.

Does my stream pass through your servers?

There are no servers. Your machine encodes and uploads directly to each platform. The project has no backend service.

Can I host the web studio on a public URL?

The studio needs the local server, which controls ffmpeg on your machine. Exposing that to the internet would let anyone start or stop your stream, so it is deliberately local-only. See the security notes in the repository before putting it behind a proxy.

How many destinations can I add?

As many as your upload bandwidth and CPU can handle. The encode happens once, so the cost per extra destination is mostly bandwidth.

Is the Android app on the Play Store?

No. It is distributed here as a signed APK.
